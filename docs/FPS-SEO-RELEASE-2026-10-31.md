# FPS content release

The supplied 40-row plan is covered by 32 new typed guides and eight existing/combined intent owners. `src/content/guides/fps-topics.ts` records the ownership decisions. Wagr, Checkmate Gaming, Fortnite wagering, skill-based gambling and trade-ups retain their existing pages. The proposed CS2 wager, pro-settings and paid-FPS pages are combined with the 1v1 comparison, settings guide and FPS money hub respectively.

The new `/fps-1v1` public landing page owns the browser game's entry intent. `/fps-duel` remains the operational lobby. The new FPS topic has one pillar and five smaller families, each containing published guides. Thirteen relevant older guides have contextual incoming links; `scripts/check-fps-guides.ts` verifies destinations, return paths, group membership and primary-keyword uniqueness. The existing all-guide validator remains the publication gate. Articles are concise task-specific explanations, not padded to the PDF's word quota, and no author credentials, current pro configs or earnings rates are fabricated.

Search Console cannibalization and query/page data were checked for 2026-10-01 through 2026-10-28. Returned overlap concerned existing non-FPS terms, not an established FPS practice cluster. This does not guarantee future ranking behavior. User-supplied Semrush estimates are research inputs, not independently verified current search volumes. Broad app-income, trade-up, esports-betting and sports-wager intents retain their existing owners.

Relevant match/fee pages server-render a five-minute cached snapshot of the latest 100 public, paid, completed-by-rounds matches inside 30 days, with eight recent anonymous settlements. Private, practice, disconnect and refunded outcomes are excluded. The data states sample scope, source time, fee and winner-credit meaning; empty and unavailable states never substitute synthetic results. Game-mechanics pages use actual PvPStrike combat functions and explicitly distinguish those numbers from native CS2 statistics.

The new SQL function is SECURITY INVOKER, executable by service_role only; its server response copies allowed fields and omits identities/invites. A partial index supports the bounded sample. Existing RLS, ledger operations, financial settings, cash configuration and match runtime are unchanged. Staging confirms index use, ACLs and actual server rendering. The public feed may retain at most one-hour-old data on upstream failure.

Validation includes all 1,167 guides, 727 unit tests, TypeScript, changed-source lint, the FPS link/intent audit, and a hosted crawl of all 34 new URLs. Browser checks exercise calculators, zero-death handling, mobile overflow, hub navigation and desktop/mobile screenshots. A hydration race in the new calculator inputs was fixed by waiting to enable them until their event handlers are ready.

Deploy the single additive migration and frontend only. Verify the production sitemap and every new canonical, repeat the browser checks, compare the production configuration baseline (allowing exactly the one new migration), and resubmit the existing sitemap to Search Console. Submission is a crawl request, not an indexing promise.
